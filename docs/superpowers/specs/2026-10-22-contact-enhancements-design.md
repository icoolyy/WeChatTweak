# 当前微信构建的非消息功能完善方案

日期：2026-10-22。状态：用户已确认设计，待实施；本文件不代表功能已经实现。

## 目标和范围

用户要求先完善原 TODO 第二类功能，消息读取和发送留到以后。本轮按用户进一步确认，只针对已经安装桥接的 App Store 微信4.1.13 / build269602 / arm64；其他版本、官网渠道和 Intel 推迟。沿用当前分支，不新增工作树，不读取聊天内容或发送消息，不自动推送。

本轮涉及原生账号身份、联系人来源、协议和本地持久化，属于架构改动。采用逐项验证后开放能力的方式，保留当前已可用的搜索和打开会话路径。

## 检查结论

- 正式安装的版本仍为4.1.13/269602，存在 App Store receipt 和桥接库。
- Adapter 只验证了已加载联系人缓存和打开会话，没有完整数据库枚举、稳定账号身份或头像 API。Qt 元数据中的候选类名不能代替 ABI 验证。
- ContactBook 只保存进程 epoch，重启即不能复用，不能直接去掉隔离来实现持久化。
- 配置对269602只有 revoke 和 multiInstance，没有自动更新补丁。旧配置里的 Sparkle/更新相关入口不能直接用于当前 App Store 版。
- 当前桥接使用鉴权请求；旧无鉴权 HTTP 快捷链接不可恢复原样。Raycast 支持通过 deeplink 和 LaunchContext 启动命令。
- config.json 的269602 verification.runtime 仍保留“contacts bridge unavailable”的早期说明，需在本轮按实际范围纠正，不能把防撤回/多开也标作验收通过。

## 方案选择

建议沿用微信进程内原生适配器，先取得稳定账号作用域，随后完善分页、持久化、头像与快捷入口。另一条路线是仅扩展现有缓存界面，但无法安全满足跨重启、跨账号隔离；读取或破解完整数据库不作为默认实现路线。

### 1. 稳定账号作用域（先决条件）

定位并验证当前登录账号的稳定原生标识，记录调用约定、所有权、线程和登录生命周期。不得把显示名、进程 PID、当前对象地址、应用路径或任意缓存联系人当成账号身份。

通过现有鉴权协议提供账号上下文。客户端只接收不可逆 accountScope 和当前 epoch，不接收原始账号标识。accountScope 使用本机私有密钥对已验证标识做 HMAC 派生；密钥不得写入 URL/日志/仓库。原始标识只在原生边界短暂使用，不保存到 Raycast。未登录、身份无法验证或不支持构建时拒绝返回作用域。

验收：同账号正常重启后作用域相同；退出状态不可用；不同账号隔离；旧 epoch 仍不能打开会话。验证不足时保留现有会话内存储，不启用跨重启功能。

### 2. 跨重启置顶和最近联系人

ContactBook 改为以已验证 accountScope 分区，epoch 继续约束当前操作。保留最近10条、置顶100条上限以及并发写入串行化、损坏数据校验。持久化条目只保存必要的稳定联系人 ID 和显示信息。

恢复记录后用当前微信服务重新验证联系人及其当前元数据，移除或标记已不可用条目，再使用新 epoch 打开；不能复用旧搜索结果直接调用。旧版只有 epoch 的数据不自动认定为当前账号，不混合迁移。

验收：同账号重启保留、不同账号不显示、延迟旧操作不能覆盖新账号分区、取消或异常不丢失其他分区。

### 3. 更完整的联系人搜索

第一步为现有真实缓存增加稳定排序分页、总数和来源，解除界面只可访问首100条的限制；每页仍最多100条，限制由服务器验证。分页游标须绑定查询、账号作用域、epoch和数据快照；缓存/会话变化时要求刷新，不混入其他快照。支持对已保存联系人进行当前状态的精确 ID 校验。

同时调查微信原生联系人查询/加载服务。只有证明其覆盖范围和线程所有权、完成真实验证后，才可以显示“完整联系人”；否则仍标注 loadedContacts，不能将分页视作完整数据库枚举。

验收：超过100条可继续查看、无重复漏项、查询或账号变化使旧游标失效、损坏/伪造游标被拒绝、缓存更新后明确刷新。

### 4. 真实头像

优先验证微信现有本地头像缓存的查找方式及账号归属。通过鉴权桥接提供受限头像数据或受控缓存结果；禁止任意文件读取、路径穿越、跟随外部符号链接及把凭证转发给远端。设置类型/大小限制，头像缺失或解码失败回退默认图标。

只有在本地缓存方案确实不能满足且微信头像来源已验证时，再单独明确网络下载策略，不接受任意联系人字段充当可访问 URL。

验收：实际联系人显示正确头像、跨账号隔离、路径和类型拒绝用例、缺失头像不影响搜索和打开会话。

### 5. 安全快捷访问

使用 Raycast deeplink 启动专用命令。URL 只携带版本和本地生成的不透明句柄，不携带桥接凭证、原始账号标识、显示名或明文联系人 ID。句柄仅能解析到本地已保存的账号作用域及联系人 ID，不能代替桥接鉴权。

打开时重新验证当前桥接身份、账号作用域和联系人，再取得当前 epoch 调用原生打开并等待确认。未知/损坏/跨账号链接明确失败。支持撤销句柄；作用域无法可靠验证时不开放持久链接。

验收：同账号重启后可用、其他账号拒绝、无 URL 凭证、打开结果确实确认、重复/无效输入不会触发任意请求。

### 6. 自动更新处理

区分应用内部更新与 App Store 管理的更新。对当前 App Store 渠道提供明确的来源/能力诊断和设置说明，不擅自修改系统全部应用的自动更新开关。

继续静态检查当前模块是否存在适用于该渠道的微信内部更新入口。发现候选必须校验原始字节及实际效果；没有证据时如实标明“未支持单独阻止 App Store 更新”，不沿用旧 Sparkle 地址或宣称补丁覆盖 App Store。

参考：Apple App Store 设置 https://support.apple.com/en-gb/guide/app-store/mchlp2257/mac 。

## 实施顺序和门槛

1. 记录静态检查与缺失接口，补齐准确的渠道/能力状态。
2. 完成稳定账号标识的只读研究与可撤销临时副本验证。需要重启/切换账号时在操作前单独协调，不强制退出正式微信。
3. 先落地账号作用域和持久化，再落地分页与精确查询、真实头像、安全快捷链接。各项有独立回归及真实验收；缺少原生证据的项不开放。
4. 同步能力协议、doctor、Raycast 管理页、README 和兼容性表；更新桥接需要重启微信，由用户掌握正式安装时机。
5. 全量测试、生产构建、独立审查；不读取/发送消息，不标记未验证平台为支持。

## 明确不包含

本轮不实现聊天记录、发送消息、自动回复、群发、图片或文件发送，不自动迁移到其他微信版本或改变系统级安全/全局更新设置。


## 2026-10-23 头像实施范围与验收补充

用户批准头像先按当前桥接epoch实现，不等待跨重启账号身份；读取同一账号factory下HeadCache内存，只有当前联系人精确ID及key/HeadInfo一致时返回图片。不存在磁盘路径接口、网络下载或持久化头像。正常输入统一为128像素以内、128KiB以内PNG，并附SHA-256。

已通过临时微信和Raycast联合验收：真实缓存命中、实际头像渲染与默认回退，以及无鉴权/旧epoch/不存在联系人/文件路径参数拒绝。验收不包括逐一人工核对全量联系人、第二账号与更多微信构建。原文“先账号作用域再头像”仅在本项当前会话实现上被此补充替代，持久化和快捷链接的原有前置条件不变。


## 2026-10-23 按需头像下载补充（用户已批准）

用户要求完整真实头像后，本地缓存之外新增微信原生头像记录的HTTPS按需补齐；3个缺失样本验证成功后，用户明确授权扩大到当前搜索结果并批量验收。该范围取代上一补充中“无网络下载”的限制，不改变不读取聊天、不向图片服务发送桥接/登录凭证、不持久化头像的要求。

外部下载仅限当前搜索实际返回的ID及原生记录中精确`wx.qlogo.cn`来源，最大4个解析/下载任务，512KiB流式上限，缩略图128像素/128KiB，64张/4MiB内存LRU；观察到会话变化或搜索移除结果时撤销许可并取消旧任务，迟到结果不能复用。无来源或下载/图片校验失败仍回退默认图标。最终构建已通过临时微信真实HTTP、配套客户端与Raycast显示验收：100条中77张可用、23回退、0接口错误。第二账号和其他微信构建仍未验收，详见头像适配记录。
