## 目标与成功条件

用户要求在当前仓库的新分支修复微信新版本兼容性和截图中的 Raycast 错误，并交付最终操作步骤。用户已选择完整功能路线，而非界面自动化替代方案。

首个验证对象是本机 Apple Silicon、App Store 微信 `4.1.13 (269602)`。本次目标为：

1. 补丁工具正确识别应用和真实目标模块，验证后支持该构建的核心补丁。
2. Raycast 可以查询真实联系人，并打开所选联系人的真实会话。
3. 管理界面准确区分 CLI 安装、补丁支持、补丁应用、桥接运行和微信登录状态。
4. 提供可执行的构建、安装、启动、验收和恢复步骤。

只有真实微信端到端验收通过，才可宣称对应功能支持 `269602`。端口返回成功、使用静态联系人、仅改变版本号或仅通过协议测试均不满足此条件。

## 已知证据与尚未证明的事项

已确认：

- 本机微信 `CFBundleVersion=269602`，应用带有 App Store receipt；宿主架构为 arm64。
- 本机安装 `wechattweak 2.0.1`；旧 `wechattweak-cli` 与 `WeChatTweak.framework` 均不存在。
- 仓库和官方远程配置包含 `31927 / 32281 / 32288 / 31960 / 34371`，不包含 `269602`。
- `Command.patch` 固定修改 `Contents/MacOS/WeChat`，配置没有目标文件字段。
- 本机主程序约 180 KiB，arm64 `__TEXT` 仅为 `0x100000000..0x10000c000`；`Contents/Resources/wechat.dylib` 约 327 MiB，并含大型 Mach-O 代码段。
- 当前 Swift 项目没有联系人服务或 HTTP 服务实现。
- 本机 Raycast 扩展仍依赖旧 CLI、framework 和 `localhost:48065`；实际搜索请求连接被拒绝。
- Raycast Homebrew 检测依赖子进程 PATH；当前 Homebrew 已安装。尚未取得 Raycast 进程的真实 PATH，不能将其误报的原因写成已证实结论。

仍需通过分析或实验验证：

- `269602` 撤回、多开等目标函数的真实模块、地址、调用约定和行为。
- 微信 4 的联系人读取、搜索及会话打开接口，以及正确的调用线程和对象生命周期。
- 当前应用签名、沙箱与加载器对桥接模块加载和通信的实际约束。
- 官网版本及 x86_64 的差异；它们不自动继承本次支持结论。

## 方案选择

采用版本适配器与配套 Raycast 扩展的完整方案。保留现有 CLI 入口，在仓库中新增版本适配和桥接模块，以及 `raycast/` 扩展源码。

未选择：

- 仅修正 Raycast 安装检测：可以改善提示，但缺失的联系人接口仍然无法使用。
- 键盘或辅助功能自动化搜索：无法提供与原接口等价的真实联系人列表及稳定身份映射；用户选择了完整路线。
- 直接复用微信 3 的 Objective-C hook 或已有旧地址：尚无证据表明其适用于微信 4.1.13。

## 架构与边界

### CLI 与补丁核心

CLI 处理应用检查、补丁计划、备份、应用和恢复；Mach-O 核心仅负责解析、校验和生成写入计划。文件解析与计划生成不得依赖 AppleScript 或 GUI 会话。

从应用 plist 直接读取构建号和显示版本，使用参数数组启动必要的系统工具，避免将应用路径插入 shell/AppleScript 字符串。

配置为补丁目标增加应用内相对文件路径、架构、补丁地址、原始字节和补丁字节。旧配置缺少目标路径时仍按原主程序解释，但新适配必须包含原始字节证据。路径必须限制在指定应用内，拒绝绝对路径、目录逃逸以及通过符号链接访问应用外文件。

配置来源顺序为显式 `-c/--config`、随此分支安装的配置；仅在用户显式指定远程 URL 时请求远程配置。诊断输出显示实际配置来源，避免本地适配被官方旧配置覆盖。远程下载须验证 HTTP 状态后解码。

应用补丁前完成所有目标、架构、Mach-O 切片、文件支持范围和原始字节检查，再开始写入。地址必须映射到对应切片的文件数据范围，不能只匹配虚拟内存范围。任一检查失败，所有原始文件保持不变。

支持检测已补丁状态。对匹配的补丁重复执行保持幂等；混合版本、未知字节或损坏文件必须明确失败，不能继续猜测地址。

备份保留整个原应用包，包括原有签名相关文件，并记录应用版本和相关文件校验值。实际应用及重签名作为一个可回退流程处理；签名失败须报告并恢复原应用包，不能只还原机器码却遗留变更后的签名。恢复时验证备份与目标应用一致，避免把旧版应用覆盖到升级后的微信；恢复过程也需处理失败，保留可人工恢复的原始备份。备份具体目录和命令参数在实现计划中固定。

### 微信版本适配器

版本适配器承载真实二进制定位结果，不把微信内部指针或私有 ABI 泄漏给 HTTP 层和 Raycast。

它对外提供联系人查询、按稳定身份打开会话、登录及能力状态。搜索结果至少包含稳定联系人 ID、显示名称和备注；头像属于可选字段，缺失时显示默认图标。联系人 ID 不得用显示名替代。

所有涉及微信内部对象的操作，按实验确认的线程规则调度；异步结果必须具有明确的所有权与超时处理。会话打开的成功响应应来自适配器确认，不能把收到请求等同于执行成功。

适配器的加载方式先在应用副本上验证。只有证明当前加载方式、签名及通信链路可行后，才实现面向用户的安装流程。加载失败、ABI 校验失败或构建不匹配时，不启动联系人能力，不运行旧地址。

### 桥接协议

新增本地桥接层，保留原接口的路径及主要数据形状：

- `GET /wechat/search?keyword=...&usePinyin=1&fuzzy=1` 返回 `{items:[...]}`，其中 `arg` 为真实稳定联系人 ID。
- `GET /wechat/start?session=...` 打开指定会话；由于旧协议使用 GET，必须同样进行鉴权，不能依赖 HTTP 方法保护此操作。
- 新增健康状态接口，返回协议版本、微信构建、登录状态及每项能力是否可用。
- 失败响应为带机器可读错误码与可读消息的 JSON；区分未登录、未支持、未就绪、无此联系人和内部调用失败。

桥接只绑定回环接口。配套 Raycast 使用本机每次安装生成的凭据鉴权；凭据只保存在当前用户可读取的位置，不放进 URL、日志、仓库或打包产物。具体存储位置须通过加载和沙箱验证后在实现计划中明确。旧客户端没有凭据时返回明确的不兼容错误，不提供无鉴权兼容模式。

限制请求体/查询长度、搜索结果数和执行超时；拒绝来自网页的跨站调用，不启用通配 CORS。健康接口仅暴露运行状态，不包含联系人或其他账号数据。请求日志不记录关键词、联系人 ID 或响应内容。

桥接层是产品能力而非端口占位服务：真实适配器不可用时应返回相应错误，不能用空列表或固定数据伪装成功。

### 配套 Raycast 扩展

在 `raycast/` 中维护可构建的扩展源码和安装说明；保留搜索联系人、打开聊天和管理三个用户流程。若复用已有 MIT 源码，保留来源和许可。

Homebrew 检测优先检查 `/opt/homebrew/bin/brew` 与 `/usr/local/bin/brew`，再检查 PATH；命令调用使用解析后的绝对路径。新版 CLI 检测 `wechattweak`，不再要求旧 framework 或旧 CLI 存在。

CLI 已安装、补丁已应用和桥接可用是独立状态。扩展根据健康接口协商能力；不支持或服务不可用时显示有针对性的操作提示，避免无限重复搜索错误。取消确认必须停止相应操作；安装及恢复动作等待真实进程结果。

扩展使用本次构建的 CLI/桥接版本；不自动从 Homebrew 安装官方 2.0.1 并假设它具备新增功能。新扩展的名称及命令说明应帮助用户区分旧扩展，最终步骤明确停用哪个旧命令。

## 实现阶段与可行性门槛

1. **定位与加载验证。** 分析真实模块；在副本验证补丁原始字节、模块加载及微信接口。记录证据，禁止以未验证地址发布支持。
2. **补丁工具修复。** 为真实 Mach-O fixture、配置解析、全量预检、备份恢复及系统工具失败路径建立回归测试，再实现兼容改动。
3. **桥接与扩展。** 按已验证适配器实现协议，再接入 Raycast；用真实搜索和会话打开完成验收。
4. **交付。** 更新 README、支持矩阵、构建脚本、安装及恢复文档，运行全部检查，逐项报告已通过与未通过的验收。

阶段之间以证据推进。若无法证明真实微信接口或加载方式可用，明确保留未完成状态，交付已验证修复和研究结果；不得将功能悄悄替换为界面自动化，也不得宣称完整问题已修复。需要改变已批准架构时再提交具体变更理由。

## 验证与验收

- Swift 回归测试覆盖旧配置兼容、新目标文件、错误原始字节、幂等、越界/零填充区、不同切片、畸形 load command、路径逃逸、任一失败不写入及恢复校验。
- CLI 测试验证含空格路径、无 GUI 会话读取版本、配置来源、退出码和签名命令失败行为。
- 协议测试覆盖真实适配器的接口边界、鉴权、输入限制、错误分类及并发/超时行为；测试替身仅用于协议隔离测试，不能代替真实微信验收。
- Raycast 完成 lint、类型检查和构建，覆盖 Homebrew 路径解析、能力判断以及取消操作。
- 在微信副本完成无写入预检、补丁及加载实验；实际安装验证前明确需要退出微信，并保留可恢复原版。
- 真实验收覆盖：登录后的中文/备注/拼音查询（适配器实际支持时）、真实身份映射、打开目标会话、未登录、停止服务、微信重启、撤回拦截及多开。拼音或某一核心补丁未通过时，在支持矩阵中逐项标明。
- 不发送测试消息、不撤回用户消息；撤回效果需要专用测试消息或用户配合，不能仅凭机器码写入判断。
